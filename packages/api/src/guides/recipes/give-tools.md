# Give the playbook tools

A reasoning function can call the tools of the tool servers that whoever runs this server set up for the playbook, naming each tool as `server/tool`, or `server/*` for every tool of a server; a connection a person added to the org is named the same way, by its name. Read the reasoning-function guide with get_guide before you write one. A reasoning function needs a model the runtime can call. Hosted Auto supplies models. On a self-hosted runtime, the operator configures a model provider: https://on.auto/docs/self-host/configuration#models.

1. Call search to see the tool servers this playbook may use and their tools; when the person named a server, give its name as `server`, and give `terms`, a few words of what the person wants done, to find the tools that fit among many. Call introspect for the input_schema of a tool before writing its arguments.
2. When no server is listed, or not the one the person wants, or search says a server's connection is `connection_broken`, follow the connect-a-service recipe: it connects the service, or reconnects it, and sets it up for what the playbook will do there; then call search again. When a server says it cannot be asked just now, tell the person why, in its words; whoever runs the server can look into it.
3. To learn what a tool answers, call it with the arguments its input_schema takes and read its `text`: that is what the function's model will see. Never make a function to look. Call a tool whose `mark` is reads with query_connection. A tool whose `mark` is acts or unmarked may change something, so call it with execute_connection, and only once the person agrees. When a prompt needs an id, such as a channel's, call the tool that lists them and take the id from its answer, confirming the choice with the person.
4. Ask the person what the function should do with the tools, and which of them it needs.
5. Write a reasoning function whose `tools` name those tools in the format of the reasoning-function guide, show it to the person, and save it with create_definition, `type` reasoning, once they agree.
6. Run it with run_definition. A run that called tools and did not succeed is not run again under its id, since a tool may have changed something: read what it called with list_playbook_events, given its `run_id`, and start a new run only if the person still wants one.
7. Tell the person what the run did with the tools, and that the function can call only the tools it names.
