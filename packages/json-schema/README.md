# @on.auto/json-schema

The runtime's one JSON Schema compiler: it compiles the input, output and view schemas a person writes in a definition of a computation, recall, interaction or prediction function and the answer schema of a reasoning function, and checks values against them. It compiles a tool's input schema only for `validate` and `dry_run` of the tool-servers bridge, which check arguments against it without calling the tool (`src/tool-reads/argument-checks.ts` there) and leave a `format` other than the six unchecked rather than refuse the schema; reasoning reads only the size and nesting of one, with `boundedJsonSchema`, before it says what a provider may refuse in it, the bridge bounds the nesting of an OpenAPI document with `nestedDeeperThan` and the size of a tool's input schema with `jsonSchemaLimits` and `utf8Bytes`, and `execute` sends the arguments unchecked, to a server that checks them itself. It sits below every package that reads a schema, so [`@on.auto/definitions`](../definitions/README.md) and the capabilities import it and it imports nothing of theirs: only `effect`, whose JSON Schema importer it compiles with.

## Compiling a schema

`compileJsonSchema(document, { what, nesting, further, otherFormats })` checks a JSON Schema's shape, size, references and loops, and compiles a validator that answers issues with JSON pointers; `what` names the schema in its issues and `nesting` bounds the values it validates. `further`, optional, is a check of what a schema cannot say, such as an order or a sum, which the output shapes of `@on.auto/definitions` give: it reads every value that is JSON within the nesting, and its issues follow the schema's within the same bound. `otherFormats`, optional, says what becomes of a `format` other than the six the compiler checks: `'refused'`, the default, refuses the schema at its pointer, and `'unchecked'` takes the schema and leaves that format unchecked, for a schema no person wrote, such as a tool's input schema; a `format` that is not text is refused either way. `jsonSchemaLimits` are its bounds, a schema of at most 65,536 bytes as JSON nested at most 64 levels with at most 20 issues named, `boundedJsonSchema` its first check alone, of the size and nesting of a schema, which reasoning also runs on the input schema of a tool, and `shapeIssues`, `isKnownKeyword` and the helpers of `json-bounds.ts`, `pointerOf`, `utf8Bytes`, `nestedDeeperThan`, `boundedIssues`, `hiddenIssues` and `mostIssues`, the checks it is built from (`src/document`).

The dialect is JSON Schema 2020-12, or draft-07 when the schema says so or keeps `definitions` without `$defs`, bounded on purpose for documents a person writes: a reference is local, `#/$defs/<name>` or `#/definitions/<name>`, and `pattern`, `patternProperties`, `if`, `then`, `else`, `contains`, the dependent keywords, `unevaluatedItems`, `unevaluatedProperties`, `additionalItems` and the dynamic and recursive anchors are refused with words that say why, as is a `format` other than the six it checks ([Formats](#formats)), with words that name the six, beside whatever type, since the shape check reads the value of each keyword whether or not it applies to the type beside it (`src/document/schema-shape.ts`); a definition that leads into a loop of `$ref`, `allOf`, `anyOf` or `oneOf` with no property or item in between is refused at its pointer (`src/document/reference-loops.ts`).

A compiled schema is `{ document, what, validate, issuesOf }`. `validate(value)` answers the value, or its issues in the words of the validator, each at its JSON pointer. `issuesOf(value)` answers the same issues, none for a value the schema takes, and gives each the rule of the schema it breaks as its `breach` (`src/document/found-issues.ts`): `kind`, for a value of another type or choice than the schema allows, a whole number among them; `missing`, for a required field or item that is not there; `unexpected`, for a field or item the schema does not allow, or a value where it allows none; `bound`, with the keyword and its value, such as `{ minLength: 6 }`, for `minLength`, `maxLength`, `minimum`, `maximum`, `exclusiveMinimum`, `exclusiveMaximum`, `multipleOf`, `minItems`, `maxItems`, `uniqueItems`, `minProperties` and `maxProperties`; and `format`, with the format a string breaks, such as `{ rule: 'format', format: 'date' }`, whose `detail` says the format and its example, `Expected a string in the format date, such as 2026-04-01`. An issue of a name that `propertyNames` bounds is `ofTheName`, at the pointer of the field that has that name, so its words can name the name rather than its value. An issue no keyword names, such as a value two branches of `oneOf` take, a value too deep, or one the further check finds, has no breach. The words a person reads are made from it by `wordedIssuesOf` of `@on.auto/definitions`, which reads the schema; this package says which rule broke and knows no words of a field.

## Formats

`stringFormats` (`src/document/string-formats.ts`) is the one place that knows the formats the compiler checks, each with its check and an example a person recognises, which the words of `@on.auto/definitions` read: `date`, `date-time` and `time`, as RFC 3339 defines `full-date`, `date-time` and `full-time`, with the lower-case `t` and `z` the RFC allows, a leap day only in a leap year and a leap second only at 23:59 in UTC; `email`, as the HTML standard defines a valid email address; `uri`, an absolute URI with a scheme, ASCII in the characters RFC 3986 allows, with no white space and each `%` followed by two hexadecimal digits, and then as `URL.canParse` decides; and `uuid`, the 8-4-4-4-12 hexadecimal form of RFC 4122 in either case. Each is one anchored check, with `URL.canParse` after it for `uri`, that runs in time linear in the string. `isFormatName` says whether a name is one of them. A format constrains a string alone, so a value of any other type passes it, as JSON Schema says, and `"type": "integer", "format": "date"` takes every integer.

The JSON Schema importer it compiles with reads `format` as an annotation and checks nothing. When the document names one of the six, `compileJsonSchema` lowers what it imported to its representation, adds to each node that carries one of the six, on itself or on one of its checks, a check of that format, `@on.auto/json-schema/isFormat` with the format as its payload, and revives the representation with the revivers the importer uses and that one (`src/document/format-checks.ts`). A reference with a `format` beside it is wrapped in a union of one member, since a suspended node takes no check. The importer merges the annotations of what `allOf`, or a `$ref` and what sits beside it, joins, so where two of them name different formats for one value it may keep one, and only that one is checked; such a schema takes no string at all in JSON Schema's terms.

## Checking a value

`schemaCheckOf(schema, { what, nesting, further })` is a check of a value that names at most three of its issues, the further check's among them, and `issuesDetail(issues, what)` the wording of the issues of a value the runtime made, each at its pointer or as the value itself at the root (`src/checking`). The checked worker of `@on.auto/definitions` checks the outputs and views of computation and recall functions with them, and the interaction capability words with `issuesDetail` what a tool it called answered. A value a person or an agent gives, the input of a run or the answer to a request, is worded instead by `wordedIssuesOf` of `@on.auto/definitions`, from the `issuesOf` of its compiled schema.

## Source

`src/document` holds the compiler and its bounds, `src/checking` the check of a value, and `src/testing` what the tests share, a compiled field and the issue of a string out of its format. The tests beside them pin the dialect and the hostile schemas it refuses.
