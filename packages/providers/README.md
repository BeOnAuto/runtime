# @on.auto/providers

The providers a person may connect: services the runtime knows how to reach, each an entry of data, an MCP server or an HTTP API described by an OpenAPI document, with how a credential reaches it and the values that differ from one connection to the next. A person who connects a provider names it and gives those values; the entry gives the rest. This package holds the schema of an entry, the reading of the entries the runtime ships, and the one resolution of a provider and what a caller gives into the addition `@on.auto/connections` takes, which then passes every check a connection given by hand passes. The runtime's code names no provider: every entry is data, handled by the same reading and the same resolution. The package sits above `@on.auto/config`, for the YAML reader, the credential check and the grammar of a placeholder, and `@on.auto/tool-servers`, whose `ServerEntrySchema` the server part of an entry picks from, and below `@on.auto/connections`, which depends on it.

## An entry

One YAML file a provider, `src/entries/<name>.yaml`, named for the entry's `name`:

| Field          | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`         | The default name of a connection to it, so a tool server's name: 1 to 32 lowercase letters, digits and hyphens, starting with a letter (`serverNameProblems` of `@on.auto/tool-servers`)                                                                                                                                                                                                                                                                                                                    |
| `title`        | What a person reads                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `description`  | One or two sentences, at most 300 characters                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `website`      | The https page where a person reads about the server and makes a credential                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `type`         | `mcp` or `openapi`, never `stdio`                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `url`          | For `mcp`, the server's address                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `document`     | For `openapi`, an https URL of the OpenAPI document, or `documents/<name>.openapi.json`, the document beside the entries named for the provider                                                                                                                                                                                                                                                                                                                                                             |
| `base_url`     | For `openapi`, where the calls go, where the document names no server                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `headers`      | Headers sent with every request, never a credential                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `query_params` | For `openapi`, query parameters sent with every call, never a credential                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `request_id`   | The header, or the key of a result's metadata, in which the server carries its own id of a request                                                                                                                                                                                                                                                                                                                                                                                                          |
| `placeholders` | The values that differ per connection, by name: `{ description, pattern, example, required? }`, or `{ description, choices: [{ value, title, sets? }] }`                                                                                                                                                                                                                                                                                                                                                    |
| `credentials`  | The ways a credential reaches the server, in the order a person is offered them, the first the default: `{ kind: secret, in, name, scheme?, description? }`, `{ kind: client_credentials, issuer, scope?, description? }`, `{ kind: none, description? }`, `{ kind: authorization, issuer, scope?, parameters?, authorization_endpoint?, token_endpoint?, revocation_endpoint?, clients?, description? }`, the way a person connects by signing in at the provider's authorization server and allowing Auto |

`ProviderEntrySchema` (`src/entry/provider-entry.ts`) checks an entry whole and names each problem at its place:

- `{name}` in `url`, `document`, `base_url`, the `issuer` of a way or one of its endpoints, a header value or a query value is a placeholder, in the grammar `placeholdersIn` of `@on.auto/config` reads, a lowercase letter and then lowercase letters, digits and underscores; each one placed is declared or set by a choice, and each one declared or set is placed somewhere. A placeholder is required unless `required: false`, and an optional one stands only as the whole value of a header or a query parameter, which is left out where it is not given.
- A placeholder of choices sets other placeholders' values through each choice's `sets`, every choice setting the same names; a name a choice sets is never declared and never asked, and its value is placed as it is written, a host with its dots among them, since nothing but a listed value is ever placed. A choice's value and what it sets hold no `$`, since a reference begins with it.
- `{client_id}` stands only in a header or a query value, and only in an entry whose every way is `client_credentials` or `authorization`, the ways whose connection holds a client id, `holdsAClientId` of `src/entry/credential-ways.ts`, the one place that names them, from which the words of the refusals are made and which `@on.auto/connections` asks too: the one the person gives on Studio's page for `client_credentials`, and for `authorization` the client the connection was made with, recorded when its consent finishes, which the serving of the connection places.
- A pattern is anchored with `^` and `$`, and its example matches it.
- An address, `url`, `base_url`, the `issuer` of a way and its `authorization_endpoint`, `token_endpoint` and `revocation_endpoint`, and a `document` but `documents/<name>.openapi.json`, writes out its scheme and `://` and holds no placeholder before its host, so no address is a placeholder whole or in its scheme. With every placeholder in its place, and for each choice with what it sets in its place, it is an https URL, or an http URL on a loopback address, so the host of every address of an entry the schema takes is read. `isPinnableTemplate` is the rule for an address with nothing to place in its placeholders, and `pinnedTemplateShape` its words, with which `@on.auto/connections` judges the issuers of the clients whoever runs the runtime registered.
- A reference, `${NAME}`, stands in a header or a query value alone, for a value that belongs to whoever runs the runtime, such as a developer token of their registration at the vendor. A header or a query value is written as a file's entry writes one, `$$` for a `$` that is no reference, since the serving substitutes the provider's references from the runtime's environment; `NAME` is then one of the variables the runtime reads for itself, which `connections.variables` may not name.
- The server part and the placeholders are checked with `credentialProblems` of `@on.auto/config`, so no value that looks like a credential ships; a placeholder's name is never judged as a credential's name, and the entry's prose, `title`, `description` and a way's `description`, is not checked for the shape of one.
- A way takes the fields of its kind and no other, and no kind is offered twice. A kind the runtime does not take is refused, so no entry ships with one.
- A way of the kind `authorization` names the authorization server by its `issuer`, which also keys the client whoever runs the runtime registered there. `consentIssuesOf` (`src/entry/credential-ways.ts`), which `@on.auto/connections` runs over the credential of such a connection too, refuses a `scope` that is not scopes separated by single spaces, `isScope` of `@on.auto/tool-servers`, the rule a granted scope is held to too, a name among the `parameters` that the authorization request sets itself, `response_type`, `response_mode`, `client_id`, `redirect_uri`, `code_challenge`, `code_challenge_method`, `state`, `scope`, `resource`, `request` and `request_uri`, while `prompt` is taken and replaces the one the request would carry, one of `authorization_endpoint` and `token_endpoint` given without the other, or `revocation_endpoint` given without them, for a server that publishes no metadata, which gives its revocation endpoint beside them where it has one, and `clients`, the client sources the server takes, `registered`, `metadata_document` and `dynamic` (`WayClientSourceSchema` of `@on.auto/tool-servers`), empty, naming one twice or out of the order the runtime takes them in, `wayClientSources`, the runtime's own order less `auto`, which no way names and a way that takes `registered` takes as well, so an entry never lists `dynamic` before a client whoever runs the runtime registered; it is `registered` alone when left out. The parameters' values are checked for a credential and a reference as the server part is, and the endpoints are judged by their values alone, since the names of the fields name a token.

The fields of a way, `wayFields`, are the one place of the placement, `in`, `name` and `scheme`, of the issuer and of the scope, and of the fields of consent, `parameters`, the three endpoints and `clients`, from which the credential of a connection picks its own; the rules of a header's name and of a scheme stay with the connection's credential, where the addition checks them. Which of them are addresses is `wayAddresses` (`src/entry/templates.ts`), the issuer and the three endpoints, from which `consentEndpoints`, the templates, the values an entry is checked by, the resolution, the hosts of a way and, in `@on.auto/connections`, the record's checks and the policy's hosts all take them.

## The shipped entries

`readProviders(shippedFiles)` (`src/reading/shipped-providers.ts`) reads the entries once, at start, from `src/entries` of the package, `shippedEntries`, with a listing of the folder, through the `ShippedFiles` of `@on.auto/operations` it is given, which the server composes, then `readYaml` of `@on.auto/config` and the schema, and answers `ProviderList`: the providers sorted by their names, not by the names of their files, and `documents`, each document beside the entries as its text and the bytes it takes, both of the bytes read through the same reader while the entry naming it is checked (`shippedDocumentOf` of `@on.auto/tool-servers`), keyed by the name the entry writes, which the tool servers describe the provider's API from, so no package reads a shipped document again. A provider is its entry and its `address`, the address its calls go to as the entry writes it: `url`, `base_url`, the first server a document beside the entries names, read at start, or the URL of a document that is not. An entry the schema refuses, a file not named for its entry, a document beside the entries that is no JSON, and one whose first server, where the entry gives no `base_url`, is missing or is no https URL, or http URL on a loopback address, without a variable, are `ProvidersInvalid`, naming each problem at the file, its line and its key, as a settings file is named, and the server stops at start. The entries ship because they sit in `src`, in the image and in the npm package alike.

## The providers whoever runs the runtime adds

`AddedProviderEntrySchema` is the schema of a provider whoever runs the runtime adds beside those it ships: `ProviderEntrySchema`, but for a `document` beside the entries, refused at `/document`, since those documents are the runtime's own and an added entry names its document by its address. The fields of an entry carry descriptions, so a JSON Schema made from it describes each. `entryProse` names the keys of an entry that hold prose, `title` and `description`, a way's among them, for a check of credentials written out that leaves a sentence alone; the schema judges the server part and the placeholders of an added entry as it judges those of a shipped one.

`joinedProviders(list, added)` answers one list of the shipped providers and those added, each at its address as the shipped entries' reading takes it (`addressOf` of `src/reading/provider-list.ts`), sorted by name, the texts of the shipped documents kept, and an added entry winning the name of a shipped one, which is then not listed.

## The resolution

`additionOfProvider(provider, given)` (`src/resolution/provider-addition.ts`) takes an entry and what a caller gives: the connection's `name`, the provider's when left out; `placeholders`, the values by name; `kind`, the credential's way, and where it is left out the first way the caller can be given, by the caller's `canBeGiven`, every way when it gives none, or the first where it can be given none, which the caller then refuses in its own words; and what is per connection, `playbooks`, `allowed` and `record_content`. It answers `{ name, type, entry, credential }`, the addition the connections package takes, with `provider` and `placeholders`, the values given, for the record: the entry is the server part with each value in its place and the choice's settings placed, the provider's references kept as it writes them, without a header or a query parameter whose optional placeholder is not given, and `{client_id}` kept for the serving to place; the credential is the way's placement, its issuer and its endpoints, with each value in its place, its scope, its parameters and its client sources, without its description. It refuses, each as an `Issue` at the pointer the caller wrote:

| What the caller gave                                         | Pointer                | Words                                                                                                                                                                    |
| ------------------------------------------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A placeholder the provider does not have                     | `/placeholders/<name>` | `The provider tracker has no placeholder team; it takes site`                                                                                                            |
| No value for a required placeholder                          | `/placeholders/<name>` | `Expected site: ` and the placeholder's description                                                                                                                      |
| A value its pattern does not match                           | `/placeholders/<name>` | `Expected a value that matches ^[a-z0-9-]{1,63}$, such as acme`                                                                                                          |
| A value none of its choices has                              | `/placeholders/<name>` | `Expected one of na or eu`                                                                                                                                               |
| A value that looks like a credential, or holds a `$`         | `/placeholders/<name>` | `Looks like a credential, which a placeholder never holds: …`, `Holds a $, which a placeholder never holds, since a reference to an environment variable begins with it` |
| In a host, a value of other than letters, digits and hyphens | `/placeholders/<name>` | `Expected letters, digits and hyphens alone, since the value names a host`                                                                                               |
| Elsewhere in an address, `/`, `?` or `#`                     | `/placeholders/<name>` | `Expected no /, ? or #, which would move the address`                                                                                                                    |
| A value the reading of the URL changes, as `..` in a path    | `/placeholders/<name>` | `Expected a value the address keeps as it is written, which the reading of this URL changes`                                                                             |
| A kind of credential the provider does not take              | `/credential/kind`     | `The provider tracker takes no client_credentials credential; it takes secret or none`                                                                                   |

A value that holds a `$` is refused for it before its pattern or its choices are asked, so a reference in a placeholder is refused in the words that say so. A value cannot move the address: the resolved URL must read as the template with the value in its place, hosts compared in lowercase as the URL parser writes them. `providerNamed(list, name)` finds a provider by its name, or refuses at `/provider`, `There is no provider named crm here`. What `@on.auto/connections` does with the addition, and where it reports a problem it finds in a field the provider resolved, is its README's.

## Translating a Discovery document

Some vendors publish a Discovery document in place of an OpenAPI document, and some of their descriptions are larger than a document may be. A document translated from a Discovery document has its manifest beside it, `src/entries/documents/<name>.manifest.json`, which says what the document is made of:

| Field                  | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `type`                 | `discovery`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `discovery`            | The address of the Discovery document                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `revision`             | The revision of the Discovery document the document beside it was made from, which the command writes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `authorization_server` | The address of the metadata of the authorization server, whose `authorization_endpoint` and `token_endpoint` the `oauth2` scheme of the document names, since a Discovery document holds neither                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `methods`              | The ids of the methods the document keeps, each an operation; the document writes its paths in the order of the first method of each                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `cuts`                 | Where the request of a method takes more than the 64 KiB an input schema may: a writable copy of a schema, `{ schema, writable_in, leaves_out, because? }`, to which the properties `writable_in` names refer in place of the schema, without its output-only properties and those `leaves_out` names, its description saying it leaves out its output-only properties and, where `leaves_out` names any, what `because` says they are, which a cut gives exactly where it leaves out more; or the properties alone a schema keeps, `{ schema, keeps, holds }`, its description saying it holds what `holds` says. Each cut is made to the Discovery document before it is translated, so a schema it leaves unreached is left out as every schema no method reaches is |

A manifest's `type`, `discovery`, says it is of a Discovery document; the other kinds are [Translating OpenAPI documents](#translating-openapi-documents)'s and [Converting Swagger documents](#converting-swagger-documents)'s. The documents are made again from their manifests by hand, never at start or at build, and committed. The command formats what it writes with the repository's formatter, `oxfmt`, so the bytes one run writes are the bytes committed. The command fetches each Discovery document and the metadata of its authorization server, and writes each document and its manifest at the revision it read; it makes every manifest's document when no name is given and the documents of the manifests named otherwise, and `<name>=<file>` reads that manifest's Discovery document from the file instead of fetching it:

```sh
pnpm --filter @on.auto/providers documents:translate
pnpm --filter @on.auto/providers documents:translate google-ads=googleads-v26.json
```

The translation, `src/translating/translate-discovery.ts`, takes each path from the method's `flatPath`, writes each method's scopes as its `security`, one requirement for each, since any one of them serves, keeps the `fields` parameter that trims an answer, and writes none of the global parameters a call never needs nor the media upload paths. A path parameter carries no `pattern`, since the runtime sends a path argument as one segment whatever it holds, a `/` encoded as `%2F`. The document requires its `oauth2` scheme at its root, `security: [{ oauth2: [] }]`, and the translation refuses a method kept whose Discovery method lists no scope, since a call of it would send no token. It writes the operations in the order of the methods kept, and the query parameters, the schemas, their keywords and their properties and the scopes by name, since a Discovery document lists them in an order that differs from one fetch to the next, so a document made again differs from the one committed only where the vendor changed what it describes.

## Translating OpenAPI documents

Some vendors publish OpenAPI documents the runtime cannot use as they are: a scheme that sends a value pasted and never a consent's token, more operations than a playbook needs, or a parameter that puts a credential in an answer. A document translated from them has a manifest of the `type` `openapi` beside it, read by the same command and the same module as a Discovery document's, of the `type` `discovery`, and sharing its `authorization_server`:

| Field                  | What it holds                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sources`              | The addresses of the vendor's OpenAPI documents in JSON, each fetched as it is named; `<name>=<file>` is refused for such a manifest, since its documents are its addresses                                                                                                                                                                                                                                                                                                                                              |
| `authorization_server` | The address of the metadata of the authorization server, whose `authorization_endpoint` and `token_endpoint` the `oauth2` scheme of the document names, as for a Discovery document                                                                                                                                                                                                                                                                                                                                      |
| `info`                 | The `title`, `version` and `description` of the document made                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `operations`           | The ids of the operations kept, each held by exactly one source and copied whole, but for its own vendor extensions, the keys that begin with `x-`, and its `security`                                                                                                                                                                                                                                                                                                                                                   |
| `path_values`          | Each a path `parameter` written as its `value` in every path, and so removed from every operation, with `because`                                                                                                                                                                                                                                                                                                                                                                                                        |
| `left_out_parameters`  | Each an `operation` kept and the `parameters` it leaves out, with `because`                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `single_strings`       | Each an `operation` kept and `at`, a JSON pointer under the schema of the JSON body of its request, to a schema written as one `string` with its description, with `because`                                                                                                                                                                                                                                                                                                                                             |
| `scheme`               | The `name` of the one `oauth2` scheme every operation requires; where an operation lists its scopes, either the keys, each inside the one before, it lists them under, `scopes_at`, as Zoom's vendor extension holds them, or the scheme of the vendor's document whose requirement in the operation lists them, `scopes_from_scheme`, as Amazon's `OAuth2` does, exactly one of the two, a scheme that writes both or neither being refused; and the endings of the scopes it leaves out, `leaving_out`, with `because` |
| `keeps_responses`      | Whether the operations keep the answers the vendor describes, or say only that they answer                                                                                                                                                                                                                                                                                                                                                                                                                               |

The translation, `src/translating/translate-openapi.ts`, writes each kept operation at its path with each value in its place, requiring the scheme at the document's root and once for each scope the operation lists and keeps, any one of which serves; `src/translating/oauth2-scheme.ts` writes the scheme and those requirements for every kind alike. The sources must name the same version of OpenAPI and the same servers, which the document names. A kept operation's `$ref` is carried with what it reaches: the document holds each component the kept operations refer to, and those the components refer to in turn, from the source that holds the operation, and no other, and refuses a reference to a component its source does not hold, and one two sources hold each their own way. The translation also refuses, in words, an operation no source holds or two hold, a parameter or a schema the manifest names that its operation lacks, a manifest's change to an operation it does not keep, a path value no kept path holds, and an operation that lists no scope the scheme keeps. The vendor's descriptions, examples and answers stay as the vendor wrote them, so the bytes one run writes differ from those committed only where the vendor changed what it describes. The command fetches the sources and the metadata and writes the document alone, its manifest being read and never written, and an address that answers with a failure refuses every kind of translation in the same words, `<address> answered 404, so nothing is translated from it`.

## Converting Swagger documents

Some vendors publish Swagger 2.0 documents, some beside OpenAPI 3 ones, whose operations the runtime cannot use as they are: it reads OpenAPI 3, and Swagger 2.0 writes parameters, bodies and schemas another way. A document converted from them has a manifest of the `type` `swagger` beside it, read by the same command and module:

| Field                     | What it holds                                                                                                                                                                                              |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sources`                 | Each the `address` of a vendor's document in JSON, Swagger 2.0 or OpenAPI 3, fetched as it is named, and the `operations` the document keeps from it; `<name>=<file>` is refused, as for OpenAPI documents |
| `authorization_server`    | The address of the metadata of the authorization server, whose `authorization_endpoint` and `token_endpoint` the `oauth2` scheme of the document names, as for the other kinds                             |
| `info`                    | The `title`, `version` and `description` of the document made                                                                                                                                              |
| `path_prefix`             | The `prefix` every kept path starts with, left out of each path with the path parameter it holds, since the entry's `base_url` gives it, with `because`                                                    |
| `headers_left_out`        | The `names` of the header parameters left out of every operation, since the runtime or the entry sends them, with `because`; the conversion writes no header, so it refuses any other                      |
| `lists_as_text`           | Why a list in a query is written as one string, its values comma-separated, which its description lists                                                                                                    |
| `boolean_values_left_out` | Why a boolean parameter keeps no list of values                                                                                                                                                            |

The conversion, `src/translating/swagger-conversion.ts`, writes an OpenAPI 3.1 document: each kept operation at its path below the prefix, with its tags, summary and description, its path and query parameters, its body as a JSON request body and its answers as JSON content, an answer the vendor does not describe named by its status. A query parameter keeps its type, format, default, values, minimum and maximum, and where its description is joined to the values of a list, the description ends its sentence first. `src/translating/schema-conversion.ts` reads each source and writes the schemas the kept operations reach, and those they reach in turn, as OpenAPI 3.1 writes them, a `nullable` type as one that takes `null` and an `example` as `examples`, and refuses a schema its source lacks and one two sources hold each their own way. The document requires its `oauth2` scheme at its root, which `oauth2-scheme.ts` writes, with no scope, since the vendor's operations name none; it writes the operations in the order the manifest keeps them and the schemas by name. The conversion also refuses, in words, an operation its source does not hold or holds twice, a parameter in a place it writes nowhere, and a path that does not start with the prefix.

## Source

`src/index.ts` is the entry point, and `translate-documents.ts` the command `documents:translate` runs, which writes what `src/translating/document-manifests.ts` translates: the command reads the manifests through `shippedFilesOnDisk(providersShippedRoots())` of `@on.auto/operations/shipped-files-on-disk`, and the file a `<name>=<file>` names, which is no file the package ships, itself, and writes each document the translation answers as a file of the package where it is shipped. `providersShippedRoots()`, of the main entry, answers the root of the package, which the server gives the reader it composes, only when it is called, so the entry loads where `import.meta.url` names no file (`src/reading/shipped-providers.test.ts`). `src/entry` holds the schema of an entry, its ways, its placeholders and the reading of its templates; `src/reading` the reading of the shipped entries, the list and what a provider reaches; `src/resolution` the resolution and the checks of a placeholder's value; `src/translating` the translations of a Discovery document and of OpenAPI documents, the conversion of Swagger documents, the `oauth2` scheme they write, and the reading of the manifests of each kind; `src/entries` the shipped entries, their documents and the manifests of those translated; `src/testing` what the tests share, and `src/testing/index.ts`, the entry `@on.auto/providers/testing`, the fixture providers `tracker`, `ledgers`, `regions` and `metrics` and their list, `fixtureProviders`, `drive` and `adverts`, whose way is consent, the one discovering its server's metadata and the other giving its endpoints with a placeholder in them, and `audiences`, whose header holds `{client_id}` beside its way of consent, `providerOf(entry, documentServer?)`, `providerListOf(...providers)` and `providersOf(...entries)`, which the tests of the resolution and of the connections use in place of the shipped ones.
