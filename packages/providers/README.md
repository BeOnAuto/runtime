# @on.auto/providers

The providers a person may connect: services the runtime knows how to reach, each an entry of data, an MCP server or an HTTP API described by an OpenAPI document, with how a credential reaches it and the values that differ from one connection to the next. A person who connects a provider names it and gives those values; the entry gives the rest. This package holds the schema of an entry, the reading of the entries the runtime ships, and the one resolution of a provider and what a caller gives into the addition `@on.auto/connections` takes, which then passes every check a connection given by hand passes. The runtime's code names no provider: every entry is data, handled by the same reading and the same resolution. The package sits above `@on.auto/config`, for the YAML reader, the credential check and the grammar of a placeholder, and `@on.auto/tool-servers`, whose `ServerEntrySchema` the server part of an entry picks from, and below `@on.auto/connections`, which depends on it.

## An entry

One YAML file a provider, `src/entries/<name>.yaml`, named for the entry's `name`:

| Field          | What it holds                                                                                                                                                                                                                                             |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`         | The default name of a connection to it, so a tool server's name: 1 to 32 lowercase letters, digits and hyphens, starting with a letter (`serverNameProblems` of `@on.auto/tool-servers`)                                                                  |
| `title`        | What a person reads                                                                                                                                                                                                                                       |
| `description`  | One or two sentences, at most 300 characters                                                                                                                                                                                                              |
| `website`      | The https page where a person reads about the server and makes a credential                                                                                                                                                                               |
| `type`         | `mcp` or `openapi`, never `stdio`                                                                                                                                                                                                                         |
| `url`          | For `mcp`, the server's address                                                                                                                                                                                                                           |
| `document`     | For `openapi`, an https URL of the OpenAPI document, or `documents/<name>.openapi.json`, the document beside the entries named for the provider                                                                                                           |
| `base_url`     | For `openapi`, where the calls go, where the document names no server                                                                                                                                                                                     |
| `headers`      | Headers sent with every request, never a credential                                                                                                                                                                                                       |
| `query_params` | For `openapi`, query parameters sent with every call, never a credential                                                                                                                                                                                  |
| `request_id`   | The header, or the key of a result's metadata, in which the server carries its own id of a request                                                                                                                                                        |
| `placeholders` | The values that differ per connection, by name: `{ description, pattern, example, required? }`, or `{ description, choices: [{ value, title, sets? }] }`                                                                                                  |
| `credentials`  | The ways a credential reaches the server, in the order a person is offered them, the first the default: `{ kind: secret, in, name, scheme?, description? }`, `{ kind: client_credentials, issuer, scope?, description? }`, `{ kind: none, description? }` |

`ProviderEntrySchema` (`src/entry/provider-entry.ts`) checks an entry whole and names each problem at its place:

- `{name}` in `url`, `document`, `base_url`, the `issuer` of a way, a header value or a query value is a placeholder, in the grammar `placeholdersIn` of `@on.auto/config` reads, a lowercase letter and then lowercase letters, digits and underscores; each one placed is declared or set by a choice, and each one declared or set is placed somewhere. A placeholder is required unless `required: false`, and an optional one stands only as the whole value of a header or a query parameter, which is left out where it is not given.
- A placeholder of choices sets other placeholders' values through each choice's `sets`, every choice setting the same names; a name a choice sets is never declared and never asked, and its value is placed as it is written, a host with its dots among them, since nothing but a listed value is ever placed. A choice's value and what it sets hold no `$`, since a reference begins with it.
- `{client_id}` stands only in a header or a query value, and only in an entry whose every way is `client_credentials`: it is the client id the person gives on Studio's page, which the serving of the connection places.
- A pattern is anchored with `^` and `$`, and its example matches it.
- An address, `url`, `base_url`, the `issuer` of a way, and a `document` but `documents/<name>.openapi.json`, writes out its scheme and `://` and holds no placeholder before its host, so no address is a placeholder whole or in its scheme. With every placeholder in its place, and for each choice with what it sets in its place, it is an https URL, or an http URL on a loopback address, so the host of every address of an entry the schema takes is read. `isPinnableTemplate` is the rule for an address with nothing to place in its placeholders, and `pinnedTemplateShape` its words, with which `@on.auto/connections` judges the issuers of the clients whoever runs the runtime registered.
- A reference, `${NAME}`, stands in a header or a query value alone, for a value that belongs to whoever runs the runtime, such as a developer token of their registration at the vendor. A header or a query value is written as a file's entry writes one, `$$` for a `$` that is no reference, since the serving substitutes the provider's references from the runtime's environment; `NAME` is then one of the variables the runtime reads for itself, which `connections.variables` may not name.
- The server part and the placeholders are checked with `credentialProblems` of `@on.auto/config`, so no value that looks like a credential ships; a placeholder's name is never judged as a credential's name, and the entry's prose, `title`, `description` and a way's `description`, is not checked for the shape of one.
- A way takes the fields of its kind and no other, and no kind is offered twice. A kind the runtime does not take is refused, so no entry ships with one.

The fields of a way, `wayFields`, are the one place of the placement, `in`, `name` and `scheme`, of the issuer and of the scope, from which the credential of a connection picks its own; the rules of a header's name and of a scheme stay with the connection's credential, where the addition checks them.

## The shipped entries

`readProviders()` (`src/reading/shipped-providers.ts`) reads the entries once, at start, from `new URL('../entries/', import.meta.url)` with a listing of the folder, through `readYaml` of `@on.auto/config` and the schema, and answers `ProviderList`: the providers sorted by their names, not by the names of their files, and the folder their documents are read from. A provider is its entry and its `address`, the address its calls go to as the entry writes it: `url`, `base_url`, the first server a document beside the entries names, read at start, or the URL of a document that is not. An entry the schema refuses, a file not named for its entry, a document beside the entries that is no JSON, and one whose first server, where the entry gives no `base_url`, is missing or is no https URL, or http URL on a loopback address, without a variable, are `ProvidersInvalid`, naming each problem at the file, its line and its key, as a settings file is named, and the server stops at start. The entries ship because they sit in `src`, in the image and in the npm package alike.

The entries this runtime ships, each verified against its vendor's documentation when it was written:

| Provider    | Server                                                    | Ways                                        | Placeholders |
| ----------- | --------------------------------------------------------- | ------------------------------------------- | ------------ |
| `github`    | MCP, `https://api.githubcopilot.com/mcp/`                 | `secret`, `Authorization: Bearer`           | none         |
| `profound`  | MCP, `https://mcp.tryprofound.com/mcp`                    | `secret`, `Authorization: Bearer`           | none         |
| `slack-api` | HTTP, the server of its document, `https://slack.com/api` | `secret`, the document's `bot_token` scheme | none         |

`slack-api`'s document is curated, beside the entries: ten Web API methods written from the vendor's method references.

`hostAlternativesOf(provider, way)` answers the hosts a way reaches, the host of its address, with a placeholder a person gives left in place, and the issuer of client credentials, once for each choice of a placeholder whose choices set the host; `@on.auto/connections` lists a provider by them. `documentServerOf(provider)` answers the provider's address where its document lies beside the entries and it gives no `base_url`, the server that document names, and nothing otherwise; `@on.auto/connections` judges that host at add and at use, as the listing judges it. `operatorVariablesOf(entry)` names the variables its references name, `operatorVariablesIn(list)` those of every provider, and `operatorValuesIn(list, environment)` the values the environment sets for them, which the serving substitutes.

## The resolution

`additionOfProvider(provider, given)` (`src/resolution/provider-addition.ts`) takes an entry and what a caller gives: the connection's `name`, the provider's when left out; `placeholders`, the values by name; `kind`, the credential's way, the first when left out; and what is per connection, `playbooks`, `allowed` and `record_content`. It answers `{ name, type, entry, credential }`, the addition the connections package takes, with `provider` and `placeholders`, the values given, for the record: the entry is the server part with each value in its place and the choice's settings placed, the provider's references kept as it writes them, without a header or a query parameter whose optional placeholder is not given, and `{client_id}` kept for the serving to place; the credential is the way's placement, issuer, with each value in its place, and scope, without its description. It refuses, each as an `Issue` at the pointer the caller wrote:

| What the caller gave                                         | Pointer                | Words                                                                                                                                                                    |
| ------------------------------------------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A placeholder the provider does not have                     | `/placeholders/<name>` | `The provider tracker has no placeholder team; it takes site`                                                                                                            |
| No value for a required placeholder                          | `/placeholders/<name>` | `Expected site: ` and the placeholder's description                                                                                                                      |
| A value its pattern does not match                           | `/placeholders/<name>` | `Expected a value that matches ^[a-z0-9-]{1,63}$, such as acme`                                                                                                          |
| A value none of its choices has                              | `/placeholders/<name>` | `Expected one of na or eu`                                                                                                                                               |
| A value that looks like a credential, or holds a `$`         | `/placeholders/<name>` | `Looks like a credential, which a placeholder never holds: …`, `Holds a $, which a placeholder never holds, since a reference to an environment variable begins with it` |
| In a host, a value of other than letters, digits and hyphens | `/placeholders/<name>` | `Expected letters, digits and hyphens alone, since the value names a host`                                                                                               |
| Elsewhere in an address, `/`, `?` or `#`                     | `/placeholders/<name>` | `Expected no /, ? or #, which would move the address`                                                                                                                    |
| A value the reading of the URL changes, as `..` in a path    | `/placeholders/<name>` | `Expected a value the address keeps as it is written, which the reading of this URL changes`                                                                             |
| A kind of credential the provider does not take              | `/credential/kind`     | `The provider tracker takes no client_credentials credential; it takes secret or none`                                                                                   |

A value cannot move the address: the resolved URL must read as the template with the value in its place, hosts compared in lowercase as the URL parser writes them. `providerNamed(list, name)` finds a provider by its name, or refuses at `/provider`, `There is no provider named crm here`. What `@on.auto/connections` does with the addition, and where it reports a problem it finds in a field the provider resolved, is its README's.

## Translating a Discovery document

Some vendors publish a Discovery document in place of an OpenAPI document, and some of their descriptions are larger than a document may be. `src/translating/translate-discovery.ts` writes a curated OpenAPI 3.1 document of the methods named, run by hand and never at start, and the result is formatted with `pnpm format` and committed beside the entries:

```sh
pnpm --filter @on.auto/providers translate-discovery <discovery document> <authorization server metadata> <curated document> <method id>...
```

It takes each path from the method's `flatPath`, writes each method's scopes as its `security`, one requirement for each, since any one of them serves, keeps the `fields` parameter that trims an answer, and writes none of the global parameters a call never needs nor the media upload paths. The `oauth2` scheme's endpoints are the `authorization_endpoint` and `token_endpoint` of the authorization server's metadata it is given, which a Discovery document does not hold. A path parameter carries no `pattern`, since the runtime refuses a `/` in a path argument whatever it says.

## Source

`src/index.ts` is the entry point. `src/entry` holds the schema of an entry, its ways, its placeholders and the reading of its templates; `src/reading` the reading of the shipped entries, the list and what a provider reaches; `src/resolution` the resolution and the checks of a placeholder's value; `src/translating` the translation of a Discovery document; `src/entries` the shipped entries and their documents; `src/testing` what the tests share, and `src/testing/index.ts`, the entry `@on.auto/providers/testing`, the fixture providers `tracker`, `ledgers`, `regions` and `metrics` and their list, `fixtureProviders`, `providerOf(entry, documentServer?)`, `providerListOf(...providers)` and `providersOf(...entries)`, which the tests of the resolution and of the connections use in place of the shipped ones.
