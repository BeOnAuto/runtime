# Terminology

This page is the glossary of Auto's playbooks. It defines the words the documentation, the product and the code use. [Availability](functions.md#availability) says what Auto runs today.

A playbook contains one brain and its workflows. The brain is the playbook's collection of reusable functions and shares its lifecycle, and runs belong to the playbook.

## Capabilities and resources

There are seven capabilities: coordination, reasoning, lookup, interaction, prediction, computation and generation. A workflow expresses coordination. Each of the other six has a function type, listed in this order:

| Capability   | Resource someone defines | Category                |
| ------------ | ------------------------ | ----------------------- |
| Coordination | Workflow                 | Workflows               |
| Reasoning    | Reasoning function       | Functions → Reasoning   |
| Lookup       | Lookup function          | Functions → Lookup      |
| Interaction  | Interaction function     | Functions → Interaction |
| Prediction   | Prediction function      | Functions → Prediction  |
| Computation  | Computation function     | Functions → Computation |
| Generation   | Generation function      | Functions → Generation  |

What each function type is for:

| Category    | Description                                                                                                     |
| ----------- | --------------------------------------------------------------------------------------------------------------- |
| Reasoning   | Use a prompt and a language model, with tools where configured, to interpret information or produce a response. |
| Lookup      | Obtain information that already exists, through one tool that only reads or from the playbook's own runs.       |
| Interaction | Exchange information with people or systems.                                                                    |
| Prediction  | Predict a quantity from the playbook's own history, with a likely range.                                        |
| Computation | Run a TypeScript program to calculate or transform data exactly.                                                |
| Generation  | Produce an asset, an image or audio, from a prompt, with a model reached through a model gateway.               |

Skill references and a separately managed tool library are still planned.

A reasoning function has a prompt and a language model; it is not limited to a model's reasoning mode. It can call the tools of operator-configured tool servers in a bounded loop. The connections people add to its organization are tool servers too, and it calls their tools the same way. [Functions](functions.md) explains when to choose each type.

## Definitions and runs

| Term             | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Playbook         | The complete system for a business responsibility, including methods, functions, workflows, relevant information and operating boundaries.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Brain            | Simply the playbook's set of functions. It is created with the playbook and shares its lifecycle, so it is never created or managed on its own. Auto's instructions to your agent use the word; most pages say "the playbook's functions".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Auto             | The product. These pages also use it for the running software, as in "start Auto" or "Auto keeps every run".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Auto Runtime     | The software you install or deploy, with npx or Docker, that stores and runs playbooks. Technical pages also call it the runtime, and call one running copy of it the server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Auto Studio      | The interface for inspecting and managing playbooks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Agent            | An AI client the user works with, such as a coding agent, that connects to Auto Runtime. It is separate from the runtime and from Auto Studio.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Connection       | Authorized access to a service. Most pages mean your agent's link to Auto, which the quick start names `auto-runtime`. A connection of an org is a tool server that a person adds through their agent, by a provider's name or as a server given by hand, and approves on Studio's page. The org owns it. Every playbook of the org may use it, or only the playbooks it names. The runtime seals a credential in its secret store and never holds it with the connection. A `reference` credential is the exception: it is the value of a variable that whoever runs the runtime sets in its environment, and nothing seals it. The tool servers the operator sets up are Auto's other connections to other services, and one tool server can serve several playbooks. Your agent's connections to its other accounts stay with your agent. |
| Method           | The business's approach to a piece of work: what evidence matters, how decisions are made and what should happen next. It needs no `Method` resource.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Definition       | A reusable function or workflow that someone saves in a playbook.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Function         | A definition of one reusable operation, with declared inputs, outputs and behavior.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Workflow         | A definition that owns one job the business does again and again, and coordinates the steps, their dependencies, conditions and handoffs that finish it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Subworkflow      | A workflow that another workflow calls and waits for.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Step             | One use of a function, another workflow or a control operation within a workflow. A step refers to its function and does not copy it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Trigger          | A condition in a workflow's document that starts a run on its own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Event trigger    | A trigger that starts a run for each event of the playbook its filters match.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Schedule trigger | A trigger that starts a run at the times its schedule names.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Schedule         | The `schedule` key of a workflow document, which holds its triggers: a cron rule, read in the time zone the schedule names or in UTC, an every period and an event trigger.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Version          | A numbered revision. A definition gets a new version each time it is saved, and each run records the version it used. A workflow document's own `document.version`, such as 1.0.0, is text the author writes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Paused           | The standing of a definition someone paused: nothing starts a run of it, neither its triggers, nor a person, nor a workflow step, until it is resumed. Runs already under way finish, and what its triggers met while it was paused is not run later. Pausing keeps its version, and the definition shows who paused it, when and why.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Description      | One or two sentences of what a definition does, in its document: a function's `description`, a workflow's `summary`, or its `title` where it has no summary. Lists of definitions show it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Overview         | Markdown the author gives beside a definition's document for the person who runs the business: why the definition exists, what it does and how it fits. Each version keeps the overview it was saved with as it was written, and an update that gives none keeps the last.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Diagram          | How a function works as a picture, which its author gives with each version: Mermaid source of a flowchart or a state diagram, or the word `none` when a picture would add nothing. Auto Studio draws a workflow from its steps, so a workflow is given no diagram.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Page             | How a workflow, a function or the whole playbook presents its results to a person: the `page` key of a definition's document, or the playbook's own. `result` shows one run, and `runs` the runs so far through views that its fold keeps of the playbook's events. A page never runs; the runtime renders it each time it is read, so Auto Studio, a chat and an agent show the same words.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Run              | A workflow or function carried out once against particular inputs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Asset            | The bytes a generation function made, or an image a tool answered a run, kept by the playbook until they expire, with an id another function takes as a reference and an address they are read at for a few minutes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Step run         | One workflow step carried out once. The run of the function or workflow it calls names that workflow run and that step, as its `within`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Attempt          | One try at a step's work, or at a run started again under its id. A retry is another attempt, not another function.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Result           | The output produced by a run.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Headline         | The first line of a run's result as the page of its subject renders it: one plain sentence, which cards and lists show alone.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Shape            | A JSON Schema the runtime owns for what a definition produces, which says what the data is and never what it measures: `series`, `categories`, `table`, `text` or `asset`. A definition that names one of the first four in `output.shape` is checked against it, and every prediction function answers a `series`, checked against that shape too. Each run of a generation function answers an `asset`, which no definition declares. Auto Studio draws a run's output from the shape the run names.                                                                                                                                                                                                                                                                                                                                       |
| Sweep            | The server's regular pass over the work that waits, such as runs to resume, answers to take and trigger starts to try again. It comes every second by default.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

Definitions, versions, runs and results are separate concepts, and an overview describes a definition without being a second source of it. A workflow can call the functions of its playbook and other workflows; a workflow called this way is a subworkflow. Starting a workflow by hand is a run, not a trigger. Sending an approval or other input to a waiting run answers that run; it does not start a new one. Timers and event waits inside a workflow are control steps, not triggers. [Workflows and runs](workflows.md) explains how versions, retries, waiting and events behave.

## Interaction

| Term              | Meaning                                                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Request           | What a run of a function waits on when it asks a person: a message, the party it goes to and when it expires. A run that asks makes one request at a time.                 |
| Party             | Whoever a request goes to. A party can answer where the request reached them, without calling the runtime, so a party need not be a caller.                                |
| Held for an agent | A request whose function writes `deliver: agent`: an agent reads it with `list_interactions` and answers it with `answer_interaction` once the person says what to answer. |
| Delivery          | How a request reaches a party through a connection the person chose: one call of the tool the function names in `deliver`.                                                 |
| Answer            | What the party or the tool gives back; it must match the answer schema and is recorded on the run once, as the run's output.                                               |
| Notification      | A request that takes no answer, so it goes through a connection; its run succeeds once it is delivered.                                                                    |
| Sign-in request   | A request that asks the person a run acts for to sign in to a site in a browser. It waits on that person by id, and only they may answer it.                               |
| Approval request  | A request a reasoning run makes when a tool asks the person the run acts for to approve an action. Only they may answer it, and only their own session may approve it.     |

An interaction function asks a system and returns its result at once, or asks a person and takes the answer later. Answering a request is not sending an event: an event goes to a waiting workflow run, and an answer goes to the run of the function that asked.

## Prediction

| Term       | Meaning                                                                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Dataset    | The rows a prediction function forecasts from, one for each series and period, folded from the playbook's events.                                                        |
| Forecaster | What answers a question to a prediction function: it backtests its methods, in order, on the series' own history and answers with the first method the history supports. |
| Backtest   | Forecasting a series' own past from earlier origins and taking each miss, the truth less the forecast, to choose a method and its range.                                 |
| Range      | The low and the high of a predicted value, set from the method's own misses in the backtest.                                                                             |
| Coverage   | The share of truths a prediction function's ranges are meant to hold, 0.8 unless its document names another.                                                             |

A prediction function, its dataset and the prediction a run returns are distinct. The forecaster keeps nothing between questions: each question backtests the series' history as the dataset holds it then.

## Orgs and callers

| Term             | Meaning                                                                                                                                                                                                                                                                                                                                        |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Org              | The runtime's name for an organization in the Auto identity service, under that organization's id, or for the org of a person signed in with none, under their subject. Every playbook and every key belongs to one org.                                                                                                                       |
| Caller           | Whoever a request acts for: a key, the local developer or a signed-in person, named on every fact it records. A run acts for the caller that started it, and a run a trigger starts acts as the playbook itself.                                                                                                                               |
| Acts for         | The person whose sign-ins a run uses, its `acts_for`, which grants the run nothing. A run a trigger starts still acts as the playbook, and acts for whoever saved or restored the version it runs, unless that person has left the org, where the runtime knows the org's members; the runs its steps start act for the same person.           |
| Key              | A credential the runtime issues itself, for a machine, a pipeline, an agent or a grant over some of an org's playbooks.                                                                                                                                                                                                                        |
| Local developer  | The caller of every request in local mode, on the developer's own machine, with every permission in every org. A server is in local mode when neither sign-in nor keys are set and it either listens only on a loopback address or its operator declares it local with `ACCESS_MODE=local`, as for a container on the developer's own machine. |
| Signed-in person | A person the Auto identity service signs in. They act in the org their sign-in names, or in their own where it names none, with the permissions their token grants, and are recorded under their subject.                                                                                                                                      |

## Supporting assets

| Term                    | Meaning                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Prompt                  | Instructions and input framing supplied to a language model by a reasoning function. The prompt is not the entire function.                                                                                                                                                                                                                                                                                      |
| Skill                   | A reusable package of task guidance and its resources. It supplies guidance rather than naming every component it uses. Planned: a reasoning function cannot use a skill yet.                                                                                                                                                                                                                                    |
| Tool                    | A calling interface for an operation, including an operation outside the playbook or a function exposed to a caller. A function exposed as a tool keeps its function type and identity.                                                                                                                                                                                                                          |
| Tool server             | An MCP server, or an HTTP API described by an OpenAPI document, whose tools functions may call: one the runtime's operator sets up, or a connection a person adds to the organization.                                                                                                                                                                                                                           |
| Provider                | A service Auto connects to. A model provider offers language models. The providers a person may connect offer tools, each an MCP server or an HTTP API Auto knows by its name, so a connection to one takes its name, its placeholders and a credential.                                                                                                                                                         |
| Placeholder             | A value of a provider's entry that differs from one connection to the next, such as the subdomain of a site or the id of an account, which the person gives when they connect.                                                                                                                                                                                                                                   |
| Registered client       | The client identity whoever runs Auto registered with an authorization server: a client id with a secret, a private key, or nothing for a public client. `connections.registered_clients` in the settings file holds them.                                                                                                                                                                                       |
| Consent                 | What a person does at an authorization server, a provider's or the one an MCP server given by hand names: signs in there and allows Auto what the way asks. A sign-in alone still means signing in to Auto.                                                                                                                                                                                                      |
| Authorization           | The kind of credential, `authorization`, by which a person connects by consent a provider's way or an MCP server given by hand that names its authorization server. Its connection's record names the issuer, the scope the person allowed and the connection's client.                                                                                                                                          |
| Authorization server    | The server that takes a person's consent and issues the tokens, named by its issuer.                                                                                                                                                                                                                                                                                                                             |
| The connection's client | The client identity a connection was made with, `client_id` and `client_source`: a registered client, a client metadata document Auto serves, or a client Auto registered itself. The connection is finished, renewed and revoked with it and no other.                                                                                                                                                          |
| Tokens                  | What an authorization server gives a connection connected by consent: an access token, a refresh token where it gives one, when the access token ends, and the scope. Auto keeps them as one sealed value in its secret store and renews them there. When the connection is removed, Auto asks the authorization server to revoke them where that server has a revocation endpoint, and forgets them either way. |
| Scope                   | What a way of consent or of client credentials asks an authorization server to allow. The provider's entry says, beside each scope, in one sentence, what a connection can do through it, and the connection's record answers the scopes asked and those granted with those words.                                                                                                                               |
| Broken                  | The state of a connection that no longer serves, as Auto found by using it. Its record says since when, Auto's sentence of why, and the kind of the break, such as `credential_refused`, when its server refused the credential the connection holds, or `credential_wanted`, when its server now asks for a credential and the connection holds none.                                                           |
| Return address          | Where the authorization server sends the person back after their consent: the page `connect-return` of the Studio the person reaches. [Let people connect by consent](../self-host/connections.md#let-people-connect-by-consent) sets out which address that is on each runtime.                                                                                                                                 |
| Start and finish        | The two operations of a consent on Studio's page: start sends the person to the authorization server to sign in and allow Auto, and finish takes the code that server sends them back with and connects the connection.                                                                                                                                                                                          |
| Language model          | A model used by a reasoning function.                                                                                                                                                                                                                                                                                                                                                                            |

## History and events

| Term            | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ledger          | The runtime's record of everything: playbooks, definitions, runs, their history and the workflows waiting on timers and events. It is a SQLite file or a PostgreSQL database.                                                                                                                                                                                                                                                                                                                 |
| Event           | A recorded fact that something happened, its type named in the past tense, as `delivery_failed` is.                                                                                                                                                                                                                                                                                                                                                                                           |
| Event data      | The fact itself: what happened, and nothing of who acted, when, or the run it belongs to.                                                                                                                                                                                                                                                                                                                                                                                                     |
| Event metadata  | Where an event is recorded, when it happened, who acted, and the definition, run and chain it belongs to.                                                                                                                                                                                                                                                                                                                                                                                     |
| Published event | An event from outside the playbook, recorded with `publish_event`.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Projection      | Data derived from the playbook's events by a defined rule: a page's views, or a prediction function's dataset.                                                                                                                                                                                                                                                                                                                                                                                |
| View            | One of the values a page keeps for `runs`, built from the playbook's events and kept up to date as they are recorded.                                                                                                                                                                                                                                                                                                                                                                         |
| Fold            | The code of a page that adds each event its filters name to its views.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Activity        | What an organization's playbooks did that a person may want to see: the requests that wait on a person, the definitions whose latest run broke, the runs, definitions and playbooks that are new, and the open comments. The runtime keeps it for the whole organization, one row for each item.                                                                                                                                                                                              |
| Seen            | A new item or a comment of the activity that the caller marked seen, or that lies at or before the place they marked everything seen through. A caller's own work and comments are seen from the start. Requests and broken definitions are never seen or unseen: they count until they are answered or resolved.                                                                                                                                                                             |
| Address         | One thing named as text: a thing of a playbook, such as `finance/runs/<run_id>` for a run or `finance/definitions/workflow/close-the-week/4/steps/do/1/review` for a step of a workflow; a thing of the organization, such as `org/connections/<id>` for a connection; or a part of either, such as `playbooks/finance/parts/ledger`. The activity names its rows by addresses, and a comment names what it is about by one. The runtime checks an address's form, not that the thing exists. |
| Comment         | What a person says about something Studio shows, of a playbook or of the organization, made where they see it, with the address of what it is about. A comment on a thing of a playbook is the playbook's, and one on a thing of the organization is the organization's own. Anyone who may read the playbook comments on it and sees the comments of others. A person hands the open comments to their agent, which acts on each; an agent never comments itself.                            |
| Part            | A piece of what Studio shows of a thing, such as a section of a playbook's Overview or a view of a definition's page, named by the thing's address followed by `/parts/<part>`. A comment on a part is about that piece of the thing.                                                                                                                                                                                                                                                         |
| Anchor          | Where on a thing a person dropped a comment, as fractions of the thing's box, from left to right and from top to bottom. A reply carries none.                                                                                                                                                                                                                                                                                                                                                |
| Pin             | The mark Studio draws at a comment's anchor, with the initials of who made it, which stays on the thing as the page scrolls or resizes.                                                                                                                                                                                                                                                                                                                                                       |
| Thread          | The comments on one address, oldest first, which a pin opens. A reply is a comment on the same address.                                                                                                                                                                                                                                                                                                                                                                                       |
| Comment rail    | Studio's list of comments, with where each is, from which a comment opens at its place.                                                                                                                                                                                                                                                                                                                                                                                                       |
| Resolved        | A comment closed by a person or an agent: `acted` once what it asked is done, or `dismissed` without acting. A resolved comment leaves the activity and stays readable as history. A comment is never edited: a person resolves it and comments again.                                                                                                                                                                                                                                        |
| Dream           | A planned, optional process that would revisit a playbook's history and suggest inspirations, such as a pattern worth investigating or a change to a method. An inspiration would be a candidate idea for a reasoning function to weigh, not a fact or an improvement. Dream would present its findings for review, or change only what the playbook has authority to change. It is not a function type.                                                                                      |

[History and events](history-and-dream.md) explains how a playbook records and reads its history.
