# @on.auto/lookup

The implementation of lookup functions. A lookup function obtains information that already exists outside the playbook through one tool that only reads: a run makes one call of the tool its document names and answers with the part of the tool's result that `read` points at, at once. It asks no model and calls no tool that may act.

User documentation is [Lookup function format](../../docs/reference/lookup-format.md), published at [on.auto/docs](https://on.auto/docs/) and served to agents as the guide `lookup-function`: the document, the mark its tool needs, the endings and the bounds. Update it alongside behaviour changes.

## The document

`parseLookupDocument(source, clock)` reads a document with the shared reader of [`@on.auto/definitions/document`](../../packages/definitions/README.md#reading-function-documents) and gives a `LookupFunctionDefinitionDocument` (`src/document`): an optional `description`, the `call`, `{ server, tool, with?, read? }`, the line its block starts on, `callLine`, the compiled `input.schema` when the document has one, and the compiled `output.schema`, which it must have. The front matter's keys are `description`, `call`, `input.schema` and `output.schema`, so `to`, `expires`, `deliver`, `model` and every other key is an issue at its line, and the message for empty front matter names `the tool it reads through`. A document without `call` is refused with `call is required`, one without an output schema with `A lookup function answers with what its tool answered, so output.schema says what that is` at the line of `call`, and a body with `A lookup function sends no message and asks no model: leave the body after the front matter empty, and say what the function does in description` at its first written line.

The call block is the interaction capability's own: `CallBlockSchema` and `compiledCallBlock` of [`@on.auto/definitions/tool-blocks`](../../packages/definitions/README.md#the-tool-blocks-of-a-capability) read and check it, so the names of the server and the tool, the templates of `with` against `input`, `today` and `now`, the arguments within 16 KiB and the JSON Pointer of `read` are refused in the words an interaction function's call is.

## The check at save

The capability's `check` (`src/marks`) asks the tool access for the one server the call names, `listServers(place, server)`, and saves a tool marked `reads` and nothing else, keeping no stripped form:

| The server answers                              | The save is                                                                                                                                                                                                                                         |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| the tool, marked `reads`                        | saved                                                                                                                                                                                                                                               |
| the tool, marked `acts`                         | `invalid_input` at the line of `call`: `The post message tool of chat is marked acts, and a lookup function calls only a tool marked reads: use an interaction function, or ask the server's author to mark it read-only.`                          |
| the tool, `unmarked`                            | the same, its mark said as `carries no mark, which counts as acts`                                                                                                                                                                                  |
| no such tool among those it offers the playbook | `invalid_input` at the line of `call`: `The tool server chat offers this playbook no tool named gone; search lists the tools it offers, and the mark of each.`, `the connection chat` for a connection                                              |
| no such server for the playbook                 | `invalid_input` at the line of `call`: `No connection or tool server named chat serves this playbook; search lists those that do, and the mark of each of their tools.`                                                                             |
| the server, unavailable                         | `unavailable`, naming the server in the words of the search, `The tool server chat could not be asked for its tools just now.`, and `A lookup function is saved once its tool is seen to be marked reads, so save it again once chat can be asked.` |

A tool the server lists more than once is saved only when every entry of that name is marked `reads`, and refused in the words of the first entry that is not. The refusal of a tool that acts adds who else may mark it by the kind of its server (`src/marks/mark-words.ts`): for a server whose entry names a provider, a connection's or a settings file's, `; the providers catalogue may also mark it reads, in its entry for <provider>`; for an entry of the settings file without one, `; whoever runs this server may also mark it reads, in the marks of its entry in tool_servers`; and for a connection without a provider, nothing more.

## A run

`makeLookupFunctionAdapter({ tools })` makes the capability for `makeDefinitionOperations`, `tools` the tool access whose `callOnce` and `listServers` it uses (`src/capability`). A run is `callRunOf` of `@on.auto/definitions/tool-blocks` with the noun `lookup function` and `requiredMark: 'reads'`: it checks the input against its schema, renders the arguments over `input`, `today` and `now`, and makes one `callOnce`, which reads the mark of the tool as its server lists it for this call and refuses one no longer marked `reads`, or listed more than once with an entry not marked `reads`, as `unopened`, `tool_not_read_only`, before anything is recorded or sent, so the run ends `unavailable` with that kind and its history holds no call. The call is recorded on the run as `tool_call_started`, which says `read_only: true`, and `tool_call_answered` or `tool_call_failed`. What it answered at `read`, checked against `output.schema` at the run and within what a run may record, is the output, `{ server, tool, read }` the record. Since every call is of a tool marked `reads`, a call that was sent and could not finish ends `unavailable`, kind `tools_unfinished`, with `because` `tool_error` or `server_failed`, which a retry may make; an answer it cannot use, or arguments the tool refused, end `conflict`, kind `unworkable`. A run under the id of one that called its tool and did not succeed is `tools_called`, because `only_read`.

The capability reaches outside, `reachesOutside`, and changes nothing there, `mayChangeOutside` false; its definitions call tools and finish within their call, and run at most `longestCallRunMs`, 70 seconds, its `longestAnyRunMs`. A run cancelled while its call is in flight goes on to its end, `whenCancelled: 'finish'`, as an interaction function's call does. It declares no facts of its own: the tool call facts are the run's. `describeOutput` says what the tool answered, `It asked the thread tool of chat; its answer: …`, in the words of `callOutputInWords`.

## Testing

`@on.auto/lookup/testing` holds documents of a lookup over the thread tool of the fake MCP server's data tools (`lookupDocument`, with `threadInput` and `repliesOutput`), and runs and checks of them against the fake MCP server of `@on.auto/tool-servers/served-fakes`, served through the tool access of `@on.auto/tool-servers/testing` (`lookupRuns`: `saved` prepares a document and runs its check, `run` prepares it and runs it on the standing clock). `annotateTool` of the fake server changes the mark a tool is listed with, so a test saves a function and then marks its tool `acts`. The check's refusals by the kind of server are tested over servers given as they are listed (`src/marks/mark-check.test.ts`).

## Source

`src/document` reads the definition, `src/marks` checks the mark of its tool when it is saved and words the refusals, `src/capability` is the capability, its guide, the public reference page served to agents as `lookup-function`, and its words, and `src/testing` what the tests share.
